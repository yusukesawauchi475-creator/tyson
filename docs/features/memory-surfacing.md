# Memory Surfacing

## コンセプト

家族ごとに記憶が浮上する機能。履歴の長さ、季節、曜日、データの種類に応じて、ホーム画面や Album の上部にランダムにバナー表示する。Hum が単なる連絡アプリではなく「記憶の熟成装置」として機能するための中核機能。

## 表示ルール（履歴長別）

履歴の長さで浮上頻度と浮上タイプが変わる:

- 1日〜1週間: なし（データ少ない、静かに待つ）
- 1週間〜1ヶ月: 週1-2回、「初日の録音」「初めての写真」
- 1〜3ヶ月: 週2-3回、「2週間前の今日」「先週一番聴かれた音声」
- 3〜6ヶ月: 週3-4回、「3ヶ月前」「季節の比較」
- 6ヶ月〜1年: 週4-5回、「半年前」「季節の変化」「成長の記録」
- 1年以上: ほぼ毎日、「1年前の今日」「2年前の今日」「去年の同じ季節」

## 浮上タイプの3レイヤー

### Layer 1: 時間ベース（実装容易）

- 「○ヶ月前の今日」シリーズ
- 「先週・先月・去年のハイライト」
- 「始めた日から◯◯日目」

### Layer 2: データ特徴ベース（中難易度）

- 「一番長い音声」「一番多く写真を送った日」
- 「毎週○曜日の傾向」
- 「季節の写真コレクション」

### Layer 3: AI分析ベース（将来、AI insight）

- 「1ヶ月前はこんな話題が多かった」
- 「最近お母さんの声が元気に聞こえる」
- 「家族の会話パターンの変化」
- wellbeing insight（長期ビジョン）

## UX 原則

- うるさすぎない: 毎回見せるとウザい
- いつも同じじゃない: ランダム性が肝
- 必ず意味がある: 「とにかく古いものを出す」じゃなく、その家族の文脈で意味を持つもの
- 閉じられる: バナーは必ず×で閉じられる

## 技術実装の方向性

- バックエンドで「この家族に今日見せるべき Memory」を計算する API
- フロントエンドは API を叩いて受け取ったバナーを表示
- 計算ロジックは最初シンプル（時間ベースのみ）、段階的に Layer 2, 3 を追加
- AI Insight は OpenAI gpt-4o-mini を活用、週次バッチで生成

## 実装優先度

- Phase A: Layer 1（時間ベース、シンプルな「1ヶ月前の今日」等）
- Phase B: Layer 2（データ特徴ベース）
- Phase C: Layer 3（AI insight、長期ビジョン）

広告撮影計画では Phase A の「2年前の今日」体験を描写する。実装は広告撮影前までに Phase A を完了させる想定。

## ゴール

ユーザーが Hum を長く使うほど体験が豊かになる構造を作る。他の連絡アプリにはない「データが積み重なる価値」を UI で体現する。
